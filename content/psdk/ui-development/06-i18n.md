This guide explains how to localize plugin text via CSV files and the `ext_text` method. The example uses the Mystery Gift plugin throughout.

## Principle

All player-visible text must be stored in a CSV file. The PSDK i18n system automatically selects the column matching the game's current language. The rules are strict:

- Never hardcode text strings in Ruby code. Always use `ext_text`.
- Each CSV file has a unique numeric identifier (the TEXT_FILE_ID).
- Each row in the CSV corresponds to an index (row 0 after the header = ID 0, row 1 = ID 1, etc.).
- Empty cells automatically fall back to the English value.

## Create the CSV file

The Mystery Gift plugin CSV file contains all the text needed for the interface. The first row is the header with language codes, then each following row is a text entry to translate.

```csv
en,fr,it,de,es,ko,kana
Code,Code,,,,,
Quit,Quitter,,,,,
Mystery Gift,Cadeau Mystere,,,,,
Enter your gift code,Entrez votre code cadeau,,,,,
Invalid code!,Code invalide !,,,,,
Gift already claimed!,Cadeau deja reclame !,,,,,
You received %s!,Vous avez recu %s !,,,,,
No gifts claimed yet,Aucun cadeau reclame,,,,,
Claim this gift?,Reclamer ce cadeau ?,,,,,
Gift received!,Cadeau recu !,,,,,
Yes,Oui,,,,,
No,Non,,,,,
```

- Row 0 after the header corresponds to ID 0 ("Code"), row 1 to ID 1 ("Quit"), etc.
- The `it`, `de`, `es`, `ko`, `kana` columns are empty: the system will automatically use the English value for those languages until they are filled in.
- `%s` in "You received %s!" is a Ruby format specifier for strings. Use `%d` for integers.

## Constants for text IDs

The CSV file has a unique identifier (here 311125). Declare one constant per CSV row to avoid magic numbers in the code.

```ruby
module UI
  module MysteryGift
    # CSV file ID for Mystery Gift i18n text
    TEXT_FILE_ID = 311_125

    # Text row IDs
    TEXT_CODE = 0
    TEXT_QUIT = 1
    TEXT_TITLE = 2
    TEXT_ENTER_CODE = 3
    TEXT_INVALID = 4
    TEXT_ALREADY_CLAIMED = 5
    TEXT_RECEIVED = 6
    TEXT_NO_GIFTS = 7
    TEXT_CLAIM = 8
    TEXT_GIFT_RECEIVED = 9
    TEXT_YES = 10
    TEXT_NO = 11
  end
end
```

- `TEXT_FILE_ID` identifies the CSV file in the PSDK i18n system.
- Each `TEXT_*` constant corresponds to a row index in the CSV. `TEXT_CODE = 0` points to the first data row ("Code").
- The constants are declared in the `UI::MysteryGift` module so they are accessible to both UI components and the GamePlay scene via `include`.

## Helper to access text

To avoid repeating `ext_text(TEXT_FILE_ID, id)` throughout the scene, define a private helper in the scene class.

```ruby
module GamePlay
  class MysteryGift < BaseCleanUpdate::FrameBalanced
    include UI::MysteryGift

    private

    # Shortcut to access Mystery Gift text
    # @param id [Integer] the text row index
    # @return [String]
    def gift_text(id)
      return ext_text(TEXT_FILE_ID, id)
    end
  end
end
```

- `include UI::MysteryGift` imports all constants (`TEXT_FILE_ID`, `TEXT_CODE`, etc.) into the scene class.
- `gift_text(id)` is a private shortcut. You write `gift_text(TEXT_TITLE)` instead of `ext_text(311_125, 2)`.
- The helper directly returns the text in the game's current language.

## Text colors

PSDK uses an indexed color system, defined in the game's font palette.

```ruby
# Indexed colors (from the game's font palette)
add_text(0, 0, 200, 18, gift_text(TEXT_TITLE), color: 0)   # black
add_text(0, 0, 200, 18, gift_text(TEXT_TITLE), color: 1)   # blue
add_text(0, 0, 200, 18, gift_text(TEXT_TITLE), color: 2)   # red
add_text(0, 0, 200, 18, gift_text(TEXT_TITLE), color: 3)   # green
add_text(0, 0, 200, 18, gift_text(TEXT_TITLE), color: 9)   # grey
add_text(0, 0, 200, 18, gift_text(TEXT_TITLE), color: 10)  # white
```

- The `color:` parameter accepts an integer corresponding to an index in the font palette.
- The most common indexes: 0 (black), 1 (blue), 2 (red), 3 (green), 9 (grey), 10 (white).

To use exact RGB colors not available in the palette, create the text without specifying `color:` (defaults to `nil`), then assign `fill_color` and `outline_color` directly.

```ruby
# Create text without indexed color, then set RGB directly
title = add_text(0, 0, 200, 18, gift_text(TEXT_TITLE))
title.fill_color = Color.new(0, 255, 136)
title.outline_color = Color.new(0, 85, 45)
```

- `color:` is optional (defaults to `nil`). You can omit it and assign colors afterwards.
- `fill_color` sets the text fill color in RGB.
- `outline_color` sets the outline color. A common pattern is to divide each channel by 3: for a fill of `(0, 255, 136)`, the outline would be `(0, 85, 45)`.

## Dynamic text with format

When a text contains format specifiers (`%s`, `%d`), Ruby's `format` method replaces the markers with the provided values.

```ruby
# Display "You received Rare Candy!" or "Vous avez recu Rare Candy !"
gift_name = gift.name
message = format(gift_text(TEXT_RECEIVED), gift_name)
add_text(0, 0, 280, 18, message, color: 1)
```

- `gift_text(TEXT_RECEIVED)` returns "You received %s!" or "Vous avez recu %s !" depending on the language.
- `format(template, gift_name)` replaces `%s` with the value of `gift_name`. Ruby's `format` method works like `sprintf`.
- The item name (`gift_name`) is not translated here because it comes from the game's database, which handles its own localization.

## Conclusion

- All player-visible text goes in a CSV file with a unique identifier (`TEXT_FILE_ID`).
- Use `ext_text(file_id, row_index)` to access text in the game's current language.
- Define a private helper (`gift_text`) in the scene to shorten `ext_text` calls.
- Declare named constants (`TEXT_TITLE`, `TEXT_RECEIVED`, etc.) for each CSV row instead of using numeric indices.
- Never hardcode text in code: always go through the CSV and `ext_text`.
- Use `format` with `%s` or `%d` for parameterized text.
